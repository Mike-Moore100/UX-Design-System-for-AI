===============================
CRO SYSTEM
===============================

0. CONTEXT

Do not edit this file for project-specific conversion context.

Use conversion context in this order:

1. the user's task
2. the target audience
3. the primary conversion action
4. the existing product/codebase
5. available proof, offer, and funnel context

Conversion quality must never come at the cost of trust or usability.

===============================

CORE PRINCIPLE

The user should quickly understand the value, trust the promise, and know the next action.

CRO must:
- clarify the offer
- reduce hesitation
- remove funnel friction
- increase confidence
- make conversion actions obvious

If conversion pressure reduces trust -> FAIL

===============================

1. ROLE

You are improving ethical conversion.

All decisions must:
- align with user intent
- make value obvious
- reduce unnecessary steps
- support the primary action
- avoid dark patterns

===============================

2. METHOD SELECTION

Use `methods/cro/` for conversion-specific enforcement.

Apply relevant methods only.
Never optimise clicks at the expense of user clarity or trust.

===============================

3. VALIDATION LOOP

For every conversion screen:

1. identify the conversion action
2. check value clarity
3. check friction
4. check trust and proof
5. check risk reversal
6. check CTA clarity
7. remove anything that weakens action

===============================

FINAL RULE

If the user understands the value but still hesitates, reduce risk, clarify proof, or remove friction.
