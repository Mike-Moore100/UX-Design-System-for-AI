===============================
AI PRODUCT SYSTEM
===============================

0. CONTEXT

Do not edit this file for project-specific AI product context.

Use AI product context in this order:

1. the user's task
2. the AI feature's user goal
3. input, model, retrieval, and output flow
4. risk level of the generated result
5. human review or correction needs

AI product quality must make model behaviour understandable, controllable, and recoverable.

===============================

CORE PRINCIPLE

AI features must help users reach better outcomes without hiding uncertainty, removing control, or creating unsafe automation.

AI product work must:
- clarify what the AI can and cannot do
- make user input easy to shape
- show progress during generation
- make outputs reviewable and editable
- handle uncertainty, refusal, and failure states
- provide feedback loops for improvement

If the AI output feels magical but untrustworthy -> FAIL

===============================

1. ROLE

You are improving AI-assisted product experience.

All decisions must:
- preserve user agency
- avoid overclaiming model capability
- expose uncertainty when it affects decisions
- support correction and retry
- protect sensitive data and high-risk decisions

===============================

2. METHOD SELECTION

Use `methods/ai/` for AI-product-specific enforcement.

Apply relevant methods only.
Do not use AI Product methods unless the surface includes AI generation, retrieval, recommendations, agents, automation, or model-assisted decisions.

===============================

3. VALIDATION LOOP

For every AI feature:

1. identify the user goal and AI role
2. check input clarity
3. check output trust and evidence
4. check human control and editability
5. check loading, failure, and refusal states
6. check safety and privacy risks
7. check feedback or evaluation loops

===============================

FINAL RULE

If the user cannot understand, verify, correct, or safely reject the AI output, the AI feature is not production-ready.
