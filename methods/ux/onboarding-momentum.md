# Onboarding Momentum

## What
Onboarding Momentum gets users to meaningful value quickly while building confidence step by step.

The first session should create progress, not setup fatigue.

## Why it matters
Users abandon when onboarding feels like work before value.

Strong onboarding:
- reduces time to value
- builds confidence
- explains only what is needed now
- creates early progress
- increases activation

Onboarding should help users do the thing, not tour the product.

## When to apply
- signup
- first-run experience
- product tours
- account setup
- AI tools
- dashboards
- team workspaces

## How to apply

- start with the user's goal
- ask only for required setup
- provide useful defaults
- guide one meaningful action
- show progress toward activation
- defer education until relevant

Users should reach value before they feel tired.

## Implementation rules

- first action must be obvious
- setup must be shorter than value delivery
- product tours must not block interaction unnecessarily
- progress must reflect meaningful completion
- empty states must guide real action
- optional configuration must be deferred

## Example

Bad:
- long profile setup before using the product
- tour explains every feature
- empty dashboard with no next action

Good:
- goal-based start
- sample data or guided first action
- progress tied to activation
- optional setup after first value

## Fail conditions

- onboarding delays value
- user must configure too much
- education is disconnected from action
- progress feels artificial
- first screen has no clear next step

## Enforcement rule

If onboarding does not create useful progress quickly, remove setup and guide the first meaningful action.
