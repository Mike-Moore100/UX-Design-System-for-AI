# Choice Architecture

## What
Choice Architecture is the design of how options are presented so users can choose confidently.

The structure of choice influences the choice itself.

## Why it matters
Too many poorly arranged options create hesitation and regret.

Good choice architecture:
- reduces decision effort
- highlights meaningful differences
- supports user goals
- prevents accidental choices
- improves completion

Choices should be easy to compare and safe to make.

## When to apply
- pricing
- settings
- filters
- onboarding choices
- plan selection
- dashboards
- configuration screens

## How to apply

- limit visible options to relevant choices
- group choices by user goal
- make differences easy to compare
- provide safe defaults
- explain recommended options
- defer rare choices

The user should understand why one option fits their goal.

## Implementation rules

- options must be mutually understandable
- recommended choices need a reason
- defaults must be safe and useful
- comparison rows must reflect decision criteria
- rare or advanced options should not dominate
- avoid manipulative defaults

## Example

Bad:
- ten equal plans
- recommended badge with no explanation
- advanced settings shown before common settings

Good:
- grouped choices
- clear plan differences
- recommended option tied to user type
- advanced choices hidden until needed

## Fail conditions

- user cannot compare options
- all options look equally important
- default benefits the business at user expense
- recommendation lacks reason
- rare options clutter common decisions

## Enforcement rule

If choices create hesitation, restructure the options around user goals and meaningful differences.
