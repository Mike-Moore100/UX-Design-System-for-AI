# Onboarding Copy

## What
Onboarding Copy helps users understand what to do first, why it matters, and how each step leads to value.

It should reduce uncertainty without over-explaining the product.

## Why it matters
Early copy shapes activation and confidence.

Good onboarding copy:
- increases completion
- reduces anxiety
- builds momentum
- explains value in context
- prevents setup mistakes

Users abandon onboarding when the effort feels disconnected from reward.

## When to apply
- signup flows
- setup checklists
- welcome screens
- product tours
- import flows
- team invites
- activation tasks

## How to apply

- explain the first meaningful outcome
- ask for information only when its purpose is clear
- keep step labels action-oriented
- show progress where useful
- use user inputs to make later steps easier
- replace generic encouragement with concrete guidance

The user should feel each step is helping them reach the product's promise.

## Implementation rules

- first screen must clarify the setup goal
- each step must explain why it matters when effort is required
- labels must describe actions, not internal processes
- progress copy must reflect real progress
- optional steps must be identified
- avoid long educational copy before action

## Example

Bad:
- "Let's get started" with no next outcome
- asks for company size without explanation
- step label says "Configuration"
- long product tour before any value

Good:
- "Set up your workspace so your team can review designs in one place"
- "Invite teammates who approve releases"
- "Connect Figma"
- progress tied to setup completion

## Fail conditions

- user does not understand why a step exists
- onboarding asks too much before value
- copy is motivational but not useful
- progress feels fake
- labels are vague

## Enforcement rule

If onboarding copy does not connect effort to value, rewrite it before adding more steps.
