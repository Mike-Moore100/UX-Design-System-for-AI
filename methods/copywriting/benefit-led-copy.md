# Benefit Led Copy

## What
Benefit Led Copy explains what the user gains from a feature, action, or product.

Features matter when they are connected to outcomes.

## Why it matters
Users do not buy feature inventories; they buy progress.

Benefit-led copy:
- clarifies value
- improves motivation
- reduces abstraction
- supports conversion
- makes product capabilities easier to compare

Feature-only copy often assumes the user will infer the value.

## When to apply
- landing pages
- feature pages
- onboarding
- pricing
- product tours
- release notes
- upgrade prompts

## How to apply

- name the feature when needed
- explain the outcome it enables
- connect the outcome to a user pain or goal
- use specifics instead of generic improvement claims
- keep proof close to large claims
- avoid benefits the product cannot deliver

The user should understand why the feature matters to them.

## Implementation rules

- every major feature claim must connect to a user benefit
- benefits must be specific
- outcome claims must be supportable
- copy must not overpromise results
- feature names must not replace explanation
- benefit order must match user priority

## Example

Bad:
- "Advanced analytics"
- "AI-powered automation"
- "Enterprise-grade workflows"

Good:
- "See which campaigns create qualified trials"
- "Turn repeated approval steps into one saved workflow"
- "Give every team the same review process"

## Fail conditions

- user cannot tell why a feature matters
- benefit is generic
- outcome is not believable
- feature list appears before value is clear
- copy promises results without mechanism

## Enforcement rule

If a feature is mentioned, connect it to a concrete user outcome or remove it.
