# Jobs-To-Be-Done Copy

## What
Jobs-To-Be-Done Copy frames messages around what the user is trying to accomplish, not just what the product does.

Users care about progress.

## Why it matters
Feature-led copy often misses the user's real motivation.

JTBD copy:
- connects features to outcomes
- improves relevance
- reduces explanation effort
- supports positioning
- makes onboarding clearer

The copy should speak to the job the user wants done.

## When to apply
- landing pages
- onboarding
- feature pages
- empty states
- upgrade prompts
- product tours
- lifecycle emails

## How to apply

- identify the user's situation
- name the progress they want
- connect product capability to that progress
- remove feature detail that does not support the job
- use examples from the user's workflow
- make the next step help them move forward

The user should see how the product helps them make progress.

## Implementation rules

- benefits must connect to user progress
- features must be translated into outcomes
- copy must match the user's current stage
- avoid internal product language
- empty states should guide the next job
- upgrade prompts must explain the new progress unlocked

## Example

Bad:
- "Advanced dashboard analytics"
- "AI-powered workspace"
- "New automation engine"

Good:
- "See which projects are slipping before standup"
- "Turn rough AI screens into production-ready UX"
- "Automate the weekly report your team already writes"

## Fail conditions

- copy describes features only
- user cannot connect feature to outcome
- message ignores the user's situation
- next step does not help progress
- internal terminology replaces user language

## Enforcement rule

If the copy explains what the product has but not what the user can accomplish, rewrite it around the job.
