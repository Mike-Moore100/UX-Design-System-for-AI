# Empty State Copy

## What
Empty State Copy explains why a surface is empty and what the user can do next.

An empty state should create momentum, not dead space.

## Why it matters
Empty states are often first-use moments.

Good empty state copy:
- reduces confusion
- teaches the product
- guides next action
- sets expectations
- improves activation

Blank screens make the product feel broken or unfinished.

## When to apply
- dashboards
- lists
- tables
- inboxes
- search results
- new projects
- filtered views
- permissions-limited views

## How to apply

- explain the empty condition
- distinguish first-use, zero-results, and permission states
- give one useful next action
- preview the value the user will unlock
- keep copy concise
- avoid blaming the user for missing data

The user should know what this space is for and what to do next.

## Implementation rules

- empty copy must match the reason for emptiness
- CTA must be specific and relevant
- first-use states should teach value
- zero-result states should support recovery
- permission states must explain access limits
- avoid generic "nothing here yet" without guidance

## Example

Bad:
- "No data"
- "Nothing here"
- "You have no items"
- empty screen with only an icon

Good:
- "Create your first project to start tracking design reviews"
- "No results match these filters. Clear filters or search again."
- "You need admin access to view billing history"

## Fail conditions

- user does not know why it is empty
- no next step exists
- copy is generic
- first-use value is unclear
- zero-results state does not help recovery

## Enforcement rule

If an empty state does not explain the condition and guide the next useful action, rewrite it.
