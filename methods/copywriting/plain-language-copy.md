# Plain Language Copy

## What
Plain Language Copy uses familiar words, direct sentence structure, and concrete meaning so users understand without extra effort.

Plain does not mean simplistic; it means usable.

## Why it matters
Users scan under pressure and vary in language ability, context, and expertise.

Plain language:
- improves comprehension
- supports accessibility
- reduces support burden
- increases trust
- helps users act faster

Complex copy creates avoidable friction.

## When to apply
- product UI
- onboarding
- forms
- help content
- legal-adjacent explanations
- pricing
- error messages
- public pages

## How to apply

- use common words where they preserve accuracy
- put the action or meaning early
- keep sentences focused
- define necessary technical terms
- remove filler and inflated adjectives
- write for the user's next decision

The user should understand the copy on the first pass.

## Implementation rules

- avoid jargon unless the audience expects it
- explain acronyms on first use where needed
- keep labels concrete
- remove vague modifiers
- use active voice when it improves clarity
- do not remove necessary detail just to make copy shorter

## Example

Bad:
- "Leverage our omnichannel enablement infrastructure"
- "Proceed with configuration"
- "An exception occurred"

Good:
- "Connect your sales channels"
- "Set up billing"
- "We could not save this change"

## Fail conditions

- user has to decode the sentence
- jargon hides the meaning
- copy is shorter but less useful
- labels do not match user intent
- important terms are undefined

## Enforcement rule

If copy can be made clearer without losing accuracy, rewrite it in plain language.
