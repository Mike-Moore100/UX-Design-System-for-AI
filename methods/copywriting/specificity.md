# Specificity

## What
Specificity makes copy concrete by naming the user, object, outcome, timeframe, number, or next step where useful.

Specific copy feels more credible.

## Why it matters
Vague copy forces users to guess.

Specific copy:
- improves trust
- clarifies value
- reduces ambiguity
- supports action
- makes proof stronger

The right detail can do more than a longer explanation.

## When to apply
- headlines
- feature descriptions
- pricing copy
- CTAs
- proof points
- onboarding
- confirmation states

## How to apply

- replace vague benefits with concrete outcomes
- name the object affected by an action
- use numbers when they are true and useful
- include timeframe when it matters
- explain what happens next
- avoid unsupported precision

Specificity must be accurate, not decorative.

## Implementation rules

- destructive actions must name the object
- CTAs should name the outcome where possible
- metrics must have context
- product claims must be supportable
- avoid fake precision
- examples should reflect real user situations

## Example

Bad:
- "Save time"
- "Delete"
- "Improve results"
- "Trusted by many"

Good:
- "Cut weekly reporting from 2 hours to 15 minutes"
- "Delete Project Alpha"
- "Generate a UX scorecard"
- "Used by 1,200 design teams"

## Fail conditions

- claim feels generic
- user does not know what changes
- CTA is ambiguous
- metric lacks context
- detail is invented or unverifiable

## Enforcement rule

If copy could apply to any product or action, make it more specific or remove it.
