# JTBD Positioning

## What
JTBD Positioning frames a product around the progress the user is trying to make, not only demographic traits or feature categories.

The message should align with the job the user is hiring the product to do.

## Why it matters
Users choose products to make progress in a situation.

Strong JTBD positioning:
- clarifies motivation
- improves audience relevance
- supports better feature prioritisation
- strengthens copy
- reveals real competitors

Demographics alone rarely explain why someone buys.

## When to apply
- product positioning
- onboarding
- landing pages
- feature pages
- pricing pages
- user research synthesis
- campaign messaging

## How to apply

- identify the situation that triggers demand
- define the progress the user wants
- name the obstacles blocking progress
- connect product capabilities to the desired job
- include emotional and social dimensions where relevant
- compare against the user's real alternatives

The user should recognise the situation and desired progress immediately.

## Implementation rules

- message must describe a concrete user situation
- outcome must be framed as progress
- features must map to the job
- alternatives must include non-product workarounds
- avoid reducing users to personas without intent
- copy must use language users would recognise

## Example

Bad:
- "For busy professionals"
- feature list without situation
- competitor set ignores spreadsheets, agencies, or manual work
- outcome is abstract

Good:
- "When your team is shipping faster than your design system can keep up..."
- clear desired progress
- product mechanism linked to the job
- alternatives framed realistically

## Fail conditions

- target audience is vague
- job is not named
- features do not connect to progress
- messaging ignores the trigger situation
- real alternatives are missing

## Enforcement rule

If the message does not explain the progress the user wants, define the job before refining positioning.
