# Message Hierarchy

## What
Message Hierarchy orders information so the user understands the product in the right sequence.

The order of ideas controls comprehension.

## Why it matters
Even strong messages fail when presented in the wrong order.

Good message hierarchy:
- helps users orient quickly
- reduces cognitive load
- supports persuasion
- makes proof more meaningful
- improves scanning

Users should not need to assemble the story themselves.

## When to apply
- homepages
- landing pages
- feature pages
- product pages
- pricing pages
- pitch sections
- launch pages

## How to apply

- start with the core promise
- explain who it is for
- show the outcome
- support with proof
- explain how it works
- end with a clear action

Message order should match the user's decision process.

## Implementation rules

- do not lead with secondary features
- proof should appear after or near the claim it supports
- details must not appear before the main idea
- section headings must advance the story
- repeated claims must be reduced
- CTA placement must match readiness

## Example

Bad:
- feature grid before explaining the product
- proof shown without claim context
- CTA appears before value is clear
- sections repeat the same idea

Good:
- clear promise
- audience and outcome explained
- proof supports the promise
- details revealed after relevance is established

## Fail conditions

- user does not know what to read first
- product story feels out of order
- proof lacks context
- feature detail overwhelms the main idea
- CTA appears before intent is built

## Enforcement rule

If the message sequence forces the user to piece together the value, reorder it around the decision path.
