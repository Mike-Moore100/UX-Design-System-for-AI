# Internal Linking

## What
Internal Linking connects related pages so users and search engines can discover, understand, and navigate the site's content.

Links explain relationships.

## Why it matters
Poor internal linking hides useful content and weakens information architecture.

Strong internal links:
- improve discoverability
- distribute authority
- support user journeys
- clarify topical relationships
- reduce dead ends

Users should never reach a useful page by accident only.

## When to apply
- docs
- blogs
- product pages
- feature pages
- comparison pages
- landing pages
- navigation and footers

## How to apply

- link related content with descriptive anchor text
- connect high-value pages from relevant contexts
- avoid isolated orphan pages
- create clear hub and spoke structures where useful
- keep navigation links crawlable
- avoid excessive unrelated links

The next useful page should be easy to find.

## Implementation rules

- anchor text must describe the destination
- important pages need inbound internal links
- links must be crawlable standard links where possible
- related content should be linked contextually
- navigation should reflect real content priority
- avoid linking every page to every page

## Example

Bad:
- "Read more" everywhere
- important pages only reachable from search
- unrelated links stuffed into content
- JS-only links that crawlers cannot follow

Good:
- descriptive contextual links
- clear navigation paths
- hub pages for related topics
- useful next-step links

## Fail conditions

- important pages are orphaned
- anchor text gives no context
- internal links feel random
- navigation hides key pages
- links are not crawlable

## Enforcement rule

If a useful page cannot be discovered through meaningful internal links, improve the linking structure.
