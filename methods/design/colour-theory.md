# Colour Theory

## What
Colour Theory is the use of colour roles, contrast, harmony, and meaning to guide attention and support decisions.

Colour must clarify the interface, not decorate it.

## Why it matters
Poor colour use creates visual noise, weak hierarchy, and accessibility problems.

Strong colour use:
- directs attention
- communicates state
- supports brand recognition
- improves readability
- reduces hesitation

## When to apply
- buttons and calls to action
- status states
- alerts and validation
- dashboards and data views
- any screen with competing visual elements

## How to apply

- assign one clear role to each colour
- reserve the primary colour for the primary action
- use muted colours for secondary surfaces and supporting content
- use state colours consistently for success, warning, error, and info
- check contrast before judging visual style
- avoid colour-only meaning

Colour should make the next action easier to see.

## Implementation rules

- primary colour must not be used for decoration
- every colour must map to a role
- maintain accessible contrast for text and controls
- limit strong accent colours to moments of action, state, or focus
- use neutral surfaces to create hierarchy without adding noise
- keep semantic state colours consistent across the product

## Example

Bad:
- multiple accent colours competing for attention
- primary colour used on decorative icons and backgrounds
- error, warning, and success states inconsistently styled

Good:
- one dominant action colour
- neutral supporting UI
- clear semantic state colours
- accessible contrast across text and controls

## Fail conditions

- colour creates confusion
- contrast is too weak
- primary action does not stand out
- colour is used only for decoration
- state meaning changes across screens

## Enforcement rule

If colour does not improve clarity, hierarchy, state, or action, reduce it or remove it.
