# Empty State Design

## What
Empty State Design turns blank or first-use states into clear guidance toward useful action.

An empty state is a moment of instruction.

## Why it matters
Empty screens often appear when users most need direction.

Good empty states:
- explain what is missing
- guide the first action
- reduce confusion
- support onboarding
- build confidence

The empty state should move the user forward.

## When to apply
- dashboards
- lists
- projects
- search results
- inboxes
- reports
- first-run product states

## How to apply

- explain why the area is empty
- show the primary next action
- provide examples when helpful
- avoid blaming the user
- offer recovery for no-result states
- keep the state visually calm

Empty states should be useful, not just cute.

## Implementation rules

- empty state must include a clear next action where appropriate
- no-result states must support query recovery
- first-use states should educate briefly
- illustration must not replace guidance
- action must match the user's likely goal
- repeated empty states must stay concise

## Example

Bad:
- blank dashboard
- "No data"
- decorative illustration with no action

Good:
- "Create your first project"
- sample data option
- search recovery suggestions
- explanation plus primary CTA

## Fail conditions

- user does not know what to do next
- empty state feels like an error
- no recovery from no results
- illustration adds noise
- first-use value is unclear

## Enforcement rule

If a state is empty, use it to explain the situation and guide the next useful action.
