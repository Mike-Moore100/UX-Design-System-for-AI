# Information Density

## What
Information Density controls how much information appears in a given area without overwhelming the user.

Density must match the task.

## Why it matters
Too much density overwhelms beginners, while too little density slows expert workflows.

Good density:
- supports scanning
- improves comparison
- protects readability
- reduces clutter
- respects task frequency

The right density depends on user intent and context.

## When to apply
- dashboards
- tables
- settings
- admin tools
- cards
- pricing pages
- mobile screens

## How to apply

- show essential information first
- group related data
- use progressive disclosure for detail
- increase density only for repeated expert tasks
- keep touch targets and readability intact
- provide filters or summaries for large data sets

Density should help the task, not impress with volume.

## Implementation rules

- dense screens need stronger hierarchy
- repeated operational tools may use higher density
- marketing pages should avoid operational density
- compact views must remain readable
- spacing must still show relationships
- density controls must not hide critical information

## Example

Bad:
- dashboard shows every metric at once
- pricing cards contain full feature documentation
- mobile screen crams desktop table columns

Good:
- summary first, details on demand
- dense table with clear columns and filters
- compact mode for expert workflows
- readable mobile reductions

## Fail conditions

- user feels overwhelmed
- important data is buried
- compact UI becomes unreadable
- density mismatches task type
- comparison becomes slower

## Enforcement rule

If density slows comprehension, reduce visible information or add structure before changing style.
