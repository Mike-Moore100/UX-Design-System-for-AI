# Grid Systems

## What
Grid Systems use consistent columns, rows, gutters, and alignment rules to organise content.

A grid gives the interface structural discipline.

## Why it matters
Without a grid, layouts feel accidental and harder to scan.

Good grids:
- improve alignment
- create consistency
- support responsive design
- reduce visual noise
- make interfaces feel more professional

Structure should be visible even when the grid is invisible.

## When to apply
- page layouts
- dashboards
- cards
- pricing tables
- forms
- content sections
- responsive screens

## How to apply

- choose a grid that matches the content
- align related elements consistently
- use gutters to separate groups
- preserve rhythm across breakpoints
- avoid arbitrary offsets
- let content priority drive layout width

The grid should support scanning and comparison.

## Implementation rules

- repeated elements must align to the same structure
- gutters must be consistent
- responsive breakpoints must preserve hierarchy
- content should not float without alignment
- grid complexity must match layout complexity
- avoid using the grid as decoration

## Example

Bad:
- cards with inconsistent widths
- misaligned headings and buttons
- mobile layout breaks comparison

Good:
- consistent columns
- aligned text and actions
- responsive stacking that preserves priority
- predictable spacing between groups

## Fail conditions

- layout feels visually unstable
- related elements do not align
- breakpoints create random order
- grid adds complexity without clarity
- comparison becomes harder

## Enforcement rule

If layout alignment feels accidental, rebuild the structure on a consistent grid.
