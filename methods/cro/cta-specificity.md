# CTA Specificity

## What
CTA Specificity makes calls to action clear, concrete, and aligned with the user's intent.

The button should describe the action or outcome, not just demand a click.

## Why it matters
Vague CTAs create uncertainty.

Specific CTAs:
- increase confidence
- clarify the next step
- reduce hesitation
- improve scanability
- align expectation with outcome

The user should know what happens next.

## When to apply
- hero sections
- pricing pages
- signup flows
- onboarding
- forms
- checkout
- empty states

## How to apply

- use action verbs tied to the outcome
- match the CTA to the user's current intent
- avoid vague labels like "Submit" when the action is specific
- support high-commitment CTAs with expectation-setting copy
- keep one dominant primary CTA per decision point
- make secondary CTAs clearly secondary

The CTA should complete the sentence "I want to..."

## Implementation rules

- primary CTA must be specific
- CTA copy must match the destination or result
- destructive CTAs must name the action
- secondary CTAs must not compete visually
- button text must fit cleanly on mobile and desktop
- do not use clever labels that reduce clarity

## Example

Bad:
- "Submit"
- "Click here"
- "Continue" with no context
- multiple equal CTAs

Good:
- "Start free trial"
- "Create account"
- "Compare plans"
- "Send password reset link"

## Fail conditions

- user cannot predict what happens after clicking
- CTA label is generic
- CTA conflicts with page promise
- too many CTAs compete
- action risk is hidden

## Enforcement rule

If the CTA does not make the next step obvious, rewrite it until the outcome is clear.
