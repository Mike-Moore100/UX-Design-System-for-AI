# Landing Page Flow

## What
Landing Page Flow orders page content so users move from relevance to belief to action.

The page should answer the user's next question before they have to search for it.

## Why it matters
Users scan landing pages in a decision sequence.

Strong page flow:
- confirms relevance quickly
- builds trust progressively
- reduces unanswered objections
- supports comparison
- makes conversion feel logical

Random section order creates decision friction.

## When to apply
- campaign pages
- homepages
- feature pages
- waitlists
- product launches
- lead capture pages
- sales pages

## How to apply

- open with the core promise and audience fit
- show the primary action early
- explain the mechanism or product clearly
- add proof before high-commitment asks
- address objections before the final CTA
- repeat CTAs only when intent has been strengthened
- remove sections that do not move the decision forward

The page should feel like a guided argument.

## Implementation rules

- first viewport must communicate relevance and next action
- proof must appear before or near conversion points
- feature sections must connect to outcomes
- objections must be answered before final CTA
- repeated CTAs must match the same offer
- section order must follow user decision logic

## Example

Bad:
- hero is vague
- testimonials appear before the user knows the product
- final CTA appears after unrelated content
- sections repeat ideas without increasing confidence

Good:
- clear promise
- product explanation
- proof
- objection handling
- final CTA with reduced uncertainty

## Fail conditions

- user has to scroll to understand the offer
- proof appears too late
- content order feels arbitrary
- CTA repeats without increasing motivation
- sections add length without answering decisions

## Enforcement rule

If the page does not move from relevance to belief to action, reorder the content before adding new sections.
