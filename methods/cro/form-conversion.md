# Form Conversion

## What
Form Conversion improves the likelihood that users complete forms accurately and confidently.

Forms should ask only for information needed to move the user forward.

## Why it matters
Forms are common abandonment points.

High-converting forms:
- reduce effort
- prevent errors
- build trust
- improve data quality
- keep momentum intact

Every unnecessary field adds friction.

## When to apply
- signup forms
- checkout forms
- lead capture
- contact forms
- onboarding questionnaires
- account settings
- booking flows

## How to apply

- remove non-essential fields
- group related fields clearly
- use appropriate input types and autocomplete
- explain why sensitive information is needed
- validate inline without interrupting typing
- make errors specific and recoverable
- preserve entered data after errors

The form should feel shorter, clearer, and safer than expected.

## Implementation rules

- required fields must be clearly indicated
- labels must remain visible
- field order must follow user logic
- input constraints must be explained before error
- submit CTA must describe the outcome
- errors must identify the field and recovery action
- privacy-sensitive asks must include context

## Example

Bad:
- vague "Submit" CTA
- hidden labels
- unnecessary phone number
- all errors shown only after submit
- entered data lost after validation fails

Good:
- concise fields
- clear labels
- helpful defaults and autocomplete
- inline recovery guidance
- CTA says what happens next

## Fail conditions

- form asks for information before value is clear
- user cannot tell which fields are required
- errors are generic
- field formatting is unexplained
- form loses progress

## Enforcement rule

If a field does not directly support the user's next step or business-critical qualification, remove it or justify it clearly.
