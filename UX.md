===============================
UX SYSTEM
===============================

0. CONTEXT

Do not edit this file for project-specific context.

Use context in this order:

1. the user's task
2. the existing product/codebase
3. layr.config.md, if present
4. a screen brief in /screens, if present

If context is missing, infer the most likely user, goal, and primary action.
Ask at most 3 questions only when the missing context would materially change the UX direction.

===============================
CORE PRINCIPLE
===============================

The best UX requires zero thinking.

===============================

1. ROLE (CRITICAL)

You are NOT designing features.

You are designing:
→ fast, obvious, low-effort user experiences

Every decision must:
- reduce time to value
- reduce cognitive load
- increase clarity
- guide behaviour
- improve conversion

FAIL:
If user has to think → FAIL

===============================

2. DECISION HIERARCHY

All decisions must pass in order:

1. Time to value
2. Cognitive load
3. Clarity
4. Trust
5. Conversion

If any fail → redesign

===============================

3. CORE PRINCIPLES

Apply at all times:

- Hick’s Law → reduce choices
- Cognitive Load → reduce thinking
- Fitts’s Law → make actions easy
- Jakob’s Law → use familiar patterns
- Peak-End Rule → strong finish
- Goal Gradient → show progress
- Zeigarnik Effect → highlight incomplete
- Default Bias → guide decisions
- Information Scent → clarify direction
- Feedback Loops → confirm action

These are rules, not suggestions.

===============================
UX VALIDATION (MANDATORY)
===============================

Use `scorecard.md` for the final Layr score.

UX must contribute evidence for:

- clarity
- cognitive load
- time to value
- task flow
- feedback
- primary action strength
- user trust

-------------------------------

LOOP

1. Build
2. Score
3. Identify weak areas
4. Fix
5. Repeat until pass

===============================

5. ZERO CONTEXT RULE

Assume:
- user is new
- user scans, not reads
- <3 seconds attention

Every screen must:
- have one clear purpose
- have one primary action
- be understood instantly

If not → FAIL

===============================

6. DECISION REDUCTION

Rules:
- minimise choices
- avoid open-ended decisions
- group related options
- hide advanced options
- pre-select defaults

FAIL:
- too many options
- hesitation

===============================

7. FLOW STRUCTURE

Flows must:

- start fast (no friction)
- guide step by step
- remove unnecessary steps
- show progress
- end with clear success

FAIL:
- unclear next step
- user gets stuck
- drop-off mid-flow

===============================
ANTI-PATTERNS (AVOID)
===============================

- multiple primary actions
- too many choices
- unclear labels
- dense content blocks
- no feedback on actions
- hidden functionality
- unnecessary steps

If present → redesign

===============================

8. PRIMARY ACTION RULE

Each screen must have:

- ONE primary action
- clear visual priority
- obvious next step

FAIL:
- competing actions
- unclear direction

===============================

9. FEEDBACK SYSTEM

Every action must:

- respond instantly
- show loading states
- confirm success
- handle errors clearly

FAIL:
- no feedback
- delayed response

===============================

10. FRICTION REMOVAL

Remove anything that:
- slows the user
- adds thinking
- adds unnecessary steps

Common issues:
- too many fields
- unnecessary clicks
- unclear wording

Rule:
shortest path to value always wins

===============================
SPEED & RESPONSE
===============================

Rules:

- instant feedback on interaction
- loading states must appear immediately
- system should feel responsive at all times

If user thinks it’s slow → it is slow

===============================

11. PROGRESS & COMPLETION

Always:

- show progress (steps, bars, states)
- highlight incomplete tasks
- guide toward completion

FAIL:
- user doesn’t know progress
- drop-off mid flow

===============================
REAL USER TEST (SIMULATION)
===============================

Validate:

- can user understand in 2 seconds?
- is next step obvious?
- does user hesitate?
- does user re-read?

If yes → FAIL

===============================

12. VALIDATION LOOP (MANDATORY)

For every output:

1. Apply all rules
2. Check time to value
3. Check cognitive load
4. Check clarity
5. Remove friction
6. Improve flow

Repeat until strong

===============================

FINAL RULE

Always choose:

- clarity > features
- speed > flexibility
- guidance > freedom
- simplicity > completeness

GOAL:

User understands instantly  
User acts without thinking  

If not → redesign

===============================
END
