# Public Pages And Docs Playbook

Use this playbook for public pages, docs, blogs, content pages, landing pages, product pages, comparison pages, and discoverable resources.

---

## Required Modules

- UX
- Design
- Accessibility
- SEO
- Copywriting
- Performance
- Marketing, when positioning or offers are present
- CRO, when the page has a conversion goal
- Analytics, when page performance or conversion must be measured

## Hard Gates

- page purpose is clear from title, H1, and opening content
- important content is visible as crawlable text
- metadata supports the page intent
- semantic structure is logical
- internal links point to useful next steps
- claims are specific and supported
- page is accessible and readable
- critical assets do not block first useful content
- content freshness is addressed when facts can change

---

## Production Rules

- Match the page to a specific search or user intent.
- Put the direct answer or core value early.
- Use headings that describe the section content.
- Keep important answers out of images, canvas, or inaccessible embeds.
- Support claims with examples, dates, product proof, or sources where needed.
- Make CTAs match the reader's stage.
- Use structured data only when it matches visible content.
- Keep performance budgets visible for media-heavy pages.

---

## Common Failure Patterns

- page title, H1, and intro describe different promises
- content is too vague to cite or trust
- important information is hidden in images
- sections use generic headings
- metadata is missing or duplicated
- internal links are vague
- page has a CTA before value is clear

---

## Evidence Required Before Scoring

- page intent is clear in title, H1, and opening content
- crawlable content answers the user's main questions
- semantic headings form a logical outline
- metadata, links, and structured data are present when relevant
- claims have nearby proof
- accessibility and performance risks are checked
